# Changelog

All notable changes to this project are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- A Cargo workspace with five crate shells: `studio-sys`, `studio-disk`, `studio-core`, `robco` and `robco-studio`.
- `robco --version` and `robco version`.
- RobCo-Core as a submodule at `external/robco-core`, and `studio-sys`, which compiles its C and wraps CRC-32, INI, `rimg_validate` and FAT16 card images.
- CI on Ubuntu, macOS and Windows: format, lints, tests, a licence check, a release build of `robco` and a Markdown link check.
- `studio-core::plan`, which reads a package's `flags.json` and lists the commands of a build: the startup code and source compiles with their three path maps, the link and `objcopy`, and the folders under `build/` those commands write into. It refuses a path field of `flags.json` that is not a plain relative path with `/`. It runs nothing.
- `studio-core::resolve`, which reads the SDK index and a package's `sdk.json`, picks package versions and tools for a target, and reads, checks and writes `robco.lock`. It refuses an `sdk.json` whose fields differ from its index entry, and a lock that is stale for the target or the host. It writes the lock through a temporary file, so a failure leaves the old lock as it was. It downloads and installs nothing.
- `studio-core::install`, which downloads, checks and installs packages and tools into the cache. It hashes a download while it streams to a temporary file, checks a package archive and its `sdk.json` before it extracts anything, checks each file, refuses links that leave a tool archive, and moves the folder into the cache with its `.robco-archive` record in one rename. The caller passes the transport. Only a local one exists. It refuses a `pipos` package that lacks a file of "Layout of pipos" with `package: manifest`, before it extracts anything, and tells its caller each step as it begins and ends.
- `robco sdk list` and `robco sdk install`, with `--index` and `--json`, by [STUDIO_CLI.md](https://github.com/RobCo-Industries/RobCo-Core/blob/main/docs/spec/STUDIO_CLI.md). A failure leaves open the `step` it happened in, so a bad archive shows `install` started, not `verify`. Tests run the program against a local index and a cache in a temporary folder, and check its output against the spec's two examples.
- `studio-net`, the `https` transport: a small HTTP/1.1 client over `rustls` with the `ring` provider. It checks certificates with the system's verifier, follows at most 5 redirects and only to `https://`, ignores the proxy variables, gives up after 30 s to connect or 60 s without a byte, and never retries. It streams the body into the caller's writer and ends the transfer when the writer refuses. It downloads an index of at most 8 MiB. Tests serve on 127.0.0.1 with a certificate they make.
- `robco sdk install` and `robco sdk list` read an `https://` index and download the archives it names, by "Where the index is" of [SDK_PACKAGE.md](https://github.com/RobCo-Industries/RobCo-Core/blob/main/docs/spec/SDK_PACKAGE.md#where-the-index-is). A local index may list `https://` archives too.
- `studio-core::codes`, the table of the spec's error codes and the exit code of each. Every error of `manifest`, `resolve`, `install` and `boot` names its code.
- `studio-sys` compiles RobCo-Core's `src/lib/rimg_seal.c` and wraps `rimg_seal` and `rimg_pack`. A test runs every vector of RobCo-Core's `tests/vectors/rimg/vectors.ini` through them.
- Seven spikes, K1 to K7, with a result page each, and an index in `docs/SPIKES.md`.
- A QEMU release in the QEMU workflow: on a tag `qemu-<version>-r<n>` it publishes the archives for Linux, macOS and Windows, QEMU's source archive, the build recipe, the notices and sources of the packed libraries, and a list of sizes and SHA-256. Any other run uploads the same files as an artifact and publishes nothing. No release has been published yet. On macOS the formula files come from homebrew-core at the commit Homebrew names, checked against its hashes, since `brew cat` needs the tap on disk. The QEMU programs are built with the build folder mapped out of their paths. Each packed program must be of the machine its archive name states, read from its header, and the macOS package is built on `macos-15`, an Apple silicon runner. No packed file may hold a path or name of the build machine: the scan searches each spelling of a path, Windows ones included, in UTF-8 and UTF-16. It also searches the build account's name in a home path or before an @, but not the bare name, which on Linux and macOS is the ordinary word `runner`. A macOS package carries a reduced Homebrew install receipt, not the receipt itself, which names the runner's home folder.
- `robco build`, with `--index` and `--json`, by [STUDIO_CLI.md](https://github.com/RobCo-Industries/RobCo-Core/blob/main/docs/spec/STUDIO_CLI.md#robco-build). It reads `robco.toml`, deletes an older `build/NAME.HTP`, reads the lock or resolves from the index, installs the packages and `gcc`, writes the lock only after a resolution, compiles, links, seals with RobCo-Core's C and validates. It writes `build/NAME.HTP` and `build/NAME.elf`. A tape whose `abi_version` or `subtype` differs from `robco.toml` fails with `build: seal`. A stale lock fails before anything is installed or written. CI builds Pip-OS's `pipos` package at a pinned commit, then builds a small project on Ubuntu, macOS and Windows with the xPack compiler, checks the tape with `rimg.py verify` on Linux and compares its SHA-256 across the three systems.
- `robco --version` names the RobCo-Core commit it was built with: `robco 0.0.0 robco-core <40 hex digits>`. With `--json` it writes one line, `{"v":1,"kind":"version","version":"0.0.0","robco_core":"..."}`. The build script reads the commit from the submodule's git files without running git. A source tree without them builds, and prints `unknown`.
- A `prerelease` workflow for `robco`. On a tag `robco-<version>-pre.<n>` it publishes the programs for Linux, macOS and Windows as a GitHub pre-release, each with its third-party notices, and `robco-SHA256SUMS`. Any other run keeps the same files as an artifact and publishes nothing. No pre-release has been published yet. The release build moved to `.github/workflows/release-build.yml`, which CI and the pre-release both call.
- `robco-studio` opens its first window: the menus, the toolbar, the rail, the Project page and the status bar, in the green, amber, blue and white schemes. Files lists the folder given on the command line, and the editor opens, edits, finds and replaces, and saves plain text with colours for C. It asks before it drops unsaved edits. Build, Run, Debug and Write card are shown as not available and do nothing. On macOS the menus are in the system menu bar. It bundles Spleen 8x16 and IBM Plex Mono.

### Changed

- A `project.title` in `robco.toml` with a control character, below U+0020 or U+007F, fails with `manifest: title`.
- A missing or bad `format` in `boot.json` fails with `package: format`.
- `robco.toml` unknown keys are reported in file order, and a `build.backend` other than `robco` counts as one.
- `external/robco-core` moves from `c6b6482` to `e004c73`, which holds the final specs in `docs/spec/`. No file that `studio-sys` compiles or includes changed.
- `external/robco-core` moves from `e004c73` to `ef5079f`, which holds the C sealer and packer and keeps the vector files' bytes on a Windows checkout. Of the files `studio-sys` compiles or includes, only `include/robco/rimg.h` changed: it gains the seal and pack declarations. The card image bytes did not change.
- Spike K1 pins RobCo-Core `c6b6482`, where the racy canary case is fixed, and no longer retries any case.
