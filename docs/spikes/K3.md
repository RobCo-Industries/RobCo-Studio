# Spike K3: RobCo-Core's C through Cargo, and a card written from Rust

## The question

1. Does RobCo-Core's host-buildable C compile and link through Cargo on Ubuntu, macOS and Windows, with clang on Windows? The code uses GNU attributes and weak symbols.
2. Does its FatFs, driven from Rust, write a card image that mtools reads and that QEMU boots?

## The method

The code is in [`spikes/k3/`](../../spikes/k3/). The CI job is [`spike-k3.yml`](../../.github/workflows/spike-k3.yml).

- A sys crate, `k3-sys`. Its `build.rs` compiles a fixed file list with the `cc` crate, `-std=gnu11` and `-DROBCO_HOST=1`. `ROBCO_CORE_DIR` names the RobCo-Core checkout. CI checks out RobCo-Core at `c8220b2731b90d0446db636a4dc986a3ce1035cb` into the workspace. No Make, no bindgen, no submodule.
- Hand-written `extern "C"` declarations in `src/lib.rs`.
- `csrc/layout.c` exports the size, alignment and field offsets of every shared struct as the C compiler sees them. A Rust test compares all 65 entries with `size_of`, `align_of` and `offset_of!`.
- Rust tests: CRC-32 of `123456789`, an INI parse with a syntax error on a known line and an `ini_get_int`, `rimg_validate` on an image packed and sealed by RobCo-Core's `tools/rimg.py`, the weak `fs_time_hook` default, and the card test.
- The card test builds a 16 MiB card in memory on `blk_ram`. Rust writes the MBR: one partition of type 0x0E at LBA 2048, as `tools/mksdimage.sh` does. Then `part_scan`, `part_open`, `fs_mkfs`, `fs_mount`, two folders, four files with one long name, `fs_unmount`. It reads two files back through the library and writes the image to disk.
- A second CI job runs in the suite's container, `robco-ci:ba6372158e4b`, the image RobCo-Core's CI uses. For the card from each system it runs `scripts/check_card.sh`: `minfo`, `mdir -/`, and `mcopy` of every file compared with `cmp`. It then builds `examples/storage` with the suite's Makefile and boots it on raspi2b through RobCo-Core's harness, `tests/harness/boot.py`, with the Rust card as the SD card. `scripts/boot_card.py` sends `cat` and `ls` commands and compares the guest's size and CRC-32 with the host's.

### The file list

These 11 files are the closed set. Every undefined symbol left after them comes from the host C library.

| File | Why |
|---|---|
| `src/lib/rimg.c` | Image validation |
| `src/lib/crc32.c` | CRC-32 |
| `src/lib/ini.c` | INI parser |
| `src/lib/part.c` | MBR scan, partition device |
| `src/lib/blk_ram.c` | RAM block device |
| `src/lib/k_string.c` | `k_memcpy`, `k_memset`, `k_memcmp`, `k_strcmp`, `k_strlen`, `k_strncpy` for `rimg.c`, `part.c`, `blk_ram.c` and `fs.c` |
| `src/lib/datetime.c` | `dt_to_fat` for `fs_glue.c` |
| `src/fs/fs.c` | File-system API |
| `src/fs/fs_glue.c` | FatFs disk layer, `fs_time_hook` |
| `third_party/fatfs/ff.c` | FatFs |
| `third_party/fatfs/ffunicode.c` | FatFs code page tables |

Include paths: `include`, `src/fs` for `ffconf.h`, `third_party/fatfs`. `src/fs/fs_strchr.c` is not needed on the host. `fs_boot.c` and `part_boot.c` are needed only for `fs_mount_boot()`, which Studio does not call.

## The result

CI runs on GitHub's runners: [45651569163](https://github.com/RobCo-Industries/RobCo-Studio/actions/runs/45651569163) with all five Windows variants, and [45651985069](https://github.com/RobCo-Industries/RobCo-Studio/actions/runs/45651985069), the final matrix, all green. Local runs are on this Mac.

| System | Compiler | Builds and links | 6 Rust tests | Changes needed |
|---|---|---|---|---|
| Ubuntu, `ubuntu-latest` | `cc`, GCC | Yes | Pass | None |
| macOS, `macos-latest` | `cc`, Apple clang | Yes | Pass | None |
| Windows, `windows-latest` | `CC=clang`, clang 20.1.8, GNU-style driver | Yes, no warning | Pass | `CC=clang` only |
| Windows, `windows-latest` | `CC=clang-cl` | Yes | Pass | Ignores `-std:gnu11`: "argument unused during compilation". Builds in its own default C mode. |
| Windows, `windows-latest` | Default, MSVC | No | Not run | `error C2061: syntax error: identifier '__attribute__'` in `klibc.h` line 32 and `rimg.h` line 69 |
| macOS, this Mac | `cc`, Apple clang | Yes | Pass | None |

The clang-cl and MSVC rows ran once, in run 45651569163, and are not in the final matrix.

Weak symbols: `fs_glue.c` has one weak definition, `fs_time_hook`, and one weak reference, `clock_get`, under `#ifdef __ELF__` only. The weak definition links on all three systems, and the test that calls it passes. No host fallback definition was needed.

The card:

| Card written on | mtools reads all 4 files, same bytes | Boots in QEMU, guest reads all 3 files, same size and CRC | Image SHA-256, first 16 hex |
|---|---|---|---|
| Ubuntu | Yes | Yes | `ee100f0f93696cff` |
| macOS | Yes | Yes | `ee100f0f93696cff` |
| Windows, clang | Yes | Yes | `ee100f0f93696cff` |
| This Mac | Yes, local mtools | Yes, one local boot, QEMU from Homebrew | `ee100f0f93696cff` |

The cards are byte for byte the same on every system: the fixed clock of `fs_time_hook` works.

What the boot proved. The guest found the partition, mounted it as FAT16 and read the files:

```
@RC stage=storage ev=part rc=ok n=1 p0_type=0x0e p0_lba=2048 p0_blocks=30720
@RC stage=storage ev=mount rc=ok total=15587840 free=15515136 cluster=512 fat=16
@RC stage=storage ev=cat rc=ok size=70000 crc=0x8b0d3f29
@RC stage=storage ev=entry name=HELLO.TXT size=48 dir=0 date=0x5c21 time=0x0000 left=0
```

`cat` of `/K3/HELLO.TXT`, `/K3/SUB/BIG.BIN` and `/K3.CFG` gave the host's size and CRC. The file with a long name holds spaces, which the guest's command line splits, so it was checked by mtools only.

## What it means for Studio

- The plan's build holds: `cc` crate, `-std=gnu11`, `-DROBCO_HOST=1`, system compiler on Linux and macOS, clang on Windows.
- On Windows, set `CC=clang`, the GNU-style driver. `clang-cl` builds too but drops `-std=gnu11` without an error, so it is the wrong choice.
- The plan's fallback for weak symbols is not needed today.
- The sys crate in S1 must differ from this spike:
  - Take RobCo-Core from the submodule at `external/robco-core`, not from `ROBCO_CORE_DIR`.
  - Use the 11 files above, plus `rimg_seal.c`.
  - Set `CC=clang` for Windows in its own config or build script, so a contributor does not set it by hand. The spike sets it only in CI.
  - Turn C warnings into errors, as `mk/host.mk` does with `-Werror`.
  - Write the MBR in Rust, as here: RobCo-Core has no MBR writer.
  - Add FAT32 cards of 64 MiB and more. The spike tested FAT16 at 16 MiB only.
  - Serialise every use of the file system: its state is global, one caller at a time.
  - Keep the layout test as is.

## What stays unknown

- FAT32 cards. Not run.
- A card larger than RAM allows. The spike holds the whole image in memory.
- Whether ARM64 Windows or Linux runners build it. Not run.
- Whether the sanitizer flags of `mk/host.mk` work through `cc`. Not tried.
- The MSVC and clang-cl rows come from one run each.
